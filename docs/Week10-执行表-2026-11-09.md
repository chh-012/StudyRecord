### Day 2 ｜ 11/10 周二 ｜ 🔌 问答接口 + SSE 流式

> **今日目标**：`POST /chat` 能返回流式回答
> **完成标准**：`curl -N` 能看到逐块输出；浏览器/前端能收到流

**⏰ 上午 1h ｜ 学/查**
- FastAPI 的 `StreamingResponse` / `EventSourceResponse`（SSE）
- 回顾 → `_reference\week03\week03-agent2-流式与多轮对话.md` §2（流式实现）
- 重点：为什么用 SSE 而不是普通响应（首字延迟/长回答）

**⏰ 上午 1.5h + 下午 2.5h ｜ 写 `/chat`**
```python
# 目标结构
class ChatRequest(BaseModel):
    question: str
    session_id: str | None = None

@router.post("/chat")
async def chat(req: ChatRequest):
    async def event_stream():
        async for token in chat_service.stream_answer(req.question, req.session_id):
            yield f"data: {json.dumps({'token': token})}\n\n"
        yield "data: [DONE]\n\n"
    return StreamingResponse(event_stream(), media_type="text/event-stream")
```
| # | 做什么 | 预期看到 | 卡住怎么办 |
|:--:|------|------|------|
| 1 | 写 `chat_service.stream_answer()`（调 LangChain stream） | 单独测试能逐字打印 | LLM 不流式 → 检查 `stream=True` |
| 2 | 接 SSE 路由 | `curl -N -X POST .../chat` 逐块输出 | 卡住 → 检查 `async for` + `yield` |
| 3 | 加 `sources` 字段（回答后附来源） | 最后一块带 `sources` | — |
| 4 | 加异常处理（LLM 报错返回 SSE error 事件） | 报错时前端能感知 | — |

**⏰ 晚上 0.5h ｜ 验证**
- 用 `curl -N` 测 3 个问题（能命中/跨文档/不存在）
- 一句话总结："流式用 SSE，是因为浏览器原生支持 EventSource 且实现比 WebSocket 简单"

> **📚 资源**：B站搜「FastAPI SSE 流式输出」「StreamingResponse」 ｜ FastAPI 响应文档（中文）｜（进阶）MDN Server-sent events
