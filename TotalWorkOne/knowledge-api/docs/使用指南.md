## 1. 项目简介

一个**笔记管理后端服务**：笔记可增删改查、可打多个标签；提供搜索接口并用 Redis 缓存加速；附带 LLM 摘要能力；最终可部署到 Linux 服务器。

它是学习计划中 **Week2「项目1」** 的综合串联产物，把 Week1（Python 进阶 / pytest / FastAPI / MySQL 索引）与 Week2（Redis 缓存 / Linux 部署 / LLM 首接触）的知识拼装成一个可运行系统。

**一句话理解各层的分工：**

```
客户端 → FastAPI（接入层·校验与路由）
           ├─→ MySQL（存储层·持久化笔记与标签，靠 SQLAlchemy ORM）
           └─→ Redis（缓存层·加速搜索，命中即返回，未命中才查库）
                └─→ 外部 LLM API（摘要能力·可选）
```

## 3. 技术栈与架构

| 层次 | 组件 | 选型 | 作用 |
|------|------|------|------|
| 接入层 | Web 框架 | **FastAPI** + uvicorn | 路由、依赖注入、自动生成 Swagger |
| 校验层 | 数据校验 | **Pydantic v2** | 请求体/响应体校验与序列化 |
| 业务层 | 数据操作 | **SQLAlchemy 2.x（同步）** | ORM 映射、SQL 生成 |
| 存储层 | 数据库 | **MySQL 8.0**（驱动 PyMySQL） | 笔记与标签持久化，UTF8MB4 |
| 缓存层 | 缓存 | **Redis 7**（redis-py） | 搜索结果缓存、防穿透 |
| 配置层 | 配置管理 | **python-dotenv** | 从 `.env` 读取连接信息与密钥 |
| 测试层 | 测试 | **pytest + httpx** | 单元/集成测试，mock 隔离外部依赖 |
| 能力层 | LLM | **httpx** 调 OpenAI 兼容接口 | 笔记摘要（可选） |

**请求处理链路：**

```
HTTP 请求
  → FastAPI 路由（main.py）
  → Pydantic 校验（schemas.py）——失败即 422
  → 缓存查询（cache.py）——命中直接返回
  → 数据库操作（crud.py）——未命中才走这里
  → 回填缓存（cache.py）
  → 统一响应包装 ApiResponse{code, message, data}
```

## 5. 数据模型

### 5.1 表结构

**notes（笔记表）**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | 主键，自增 | 笔记 ID |
| title | VARCHAR(200) | 非空，**索引** | 标题 |
| content | TEXT | 可空 | 内容 |
| created_at | DATETIME | 非空 | 创建时间（UTC） |
| updated_at | DATETIME | 非空，自动更新 | 更新时间（UTC），列表与搜索按它倒序 |

**tags（标签表）**

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| id | INT | 主键，自增 | 标签 ID |
| name | VARCHAR(50) | 非空，**唯一索引** | 标签名称 |

**note_tags（关联表）**

| 字段 | 类型 | 约束 |
|------|------|------|
| note_id | INT | 主键之一，外键 → notes.id（级联删除） |
| tag_id | INT | 主键之一，外键 → tags.id（级联删除） |

### 5.2 关系图

```
notes  ──<  note_tags  >──  tags
(1) 多对多：一条笔记可有多个标签，一个标签可属于多条笔记
删除笔记时，note_tags 中的关联记录由外键 ON DELETE CASCADE 自动清理
```

### 5.3 设计要点

- **标题与标签名建索引**：对应 Week1 学习的索引知识，加速按标题查询与标签筛选。
- **标签名唯一索引**：保证同名标签在全库唯一，配合"自动创建"逻辑不会产生重复标签。
- **时间统一按 UTC 存储**：MySQL 的 `DATETIME` 不带时区，统一用 naive UTC，避免跨时区歧义。

## 6. API 接口详解

**基础地址**：`http://127.0.0.1:8000`
**在线文档**：`http://127.0.0.1:8000/docs`（Swagger UI，可直接点击调试）
**OpenAPI**：`http://127.0.0.1:8000/openapi.json`

### 6.0 统一响应结构

所有接口（含错误）都返回同一外壳：

```json
{
  "code": 0,          // 0 = 成功；非 0 = 失败（通常等于 HTTP 状态码）
  "message": "ok",    // 提示信息
  "data": {}          // 业务数据；失败时为 null
}
```

**状态码约定：**

| HTTP 状态码 | code | 含义 |
|:---:|:---:|------|
| 200 | 0 | 查询/更新/删除成功 |
| 201 | 0 | 创建成功 |
| 404 | 404 | 资源不存在 |
| 422 | 422 | 参数校验失败 |
| 500 | — | 未捕获异常（返回 FastAPI 默认的错误响应，非统一结构） |
| 502 | 502 | 下游 LLM 调用失败 |

> 说明：业务类错误（404/422/502）均由本项目主导返回统一结构；仅"未捕获的意外异常"由框架兜底，返回 500。

### 6.1 创建笔记 `POST /api/notes`

**请求体**

| 字段 | 类型 | 必填 | 约束 |
|------|------|:---:|------|
| title | string | 是 | 去空白后 1–200 字符，不可全为空白 |
| content | string \| null | 否 | 可为空 |
| tags | string[] | 否 | 默认 `[]`；自动去空白、去重、丢弃空串 |

**请求示例**

```bash
curl -X POST http://127.0.0.1:8000/api/notes \
  -H "Content-Type: application/json" \
  -d '{"title":"FastAPI 学习笔记","content":"路由、依赖注入与 Pydantic 校验","tags":["python","web","python"]}'
```

> 注意 `tags` 里传了两个 `python`，服务端会自动去重，最终只保留一个。

**响应示例（201）**

```json
{
  "code": 0,
  "message": "创建成功",
  "data": {
    "id": 1,
    "title": "FastAPI 学习笔记",
    "content": "路由、依赖注入与 Pydantic 校验",
    "tags": ["python", "web"],
    "created_at": "2026-10-11T12:00:00",
    "updated_at": "2026-10-11T12:00:00"
  }
}
```

**行为说明**
- 标签 `python`、`web` 若不存在会自动创建；已存在则直接关联。
- 创建后会自动清空搜索缓存（保证搜索能查到新数据）。

**校验失败示例（422）**

```json
{
  "code": 422,
  "message": "请求参数校验失败",
  "data": [
    {
      "type": "string_too_short",
      "loc": ["body", "title"],
      "msg": "String should have at least 1 character",
      "input": ""
    }
  ]
}
```

### 6.6 搜索笔记 `GET /api/notes/search`

> ⭐ 本项目核心接口，体现 Redis 缓存加速与防穿透设计。

**查询参数**

| 参数 | 类型 | 必填 | 约束 | 说明 |
|------|------|:---:|------|------|
| q | string | 条件必填 | ≤ 100 字符 | 关键词，对**标题和内容**做 `LIKE %q%` 模糊匹配 |
| tag | string | 条件必填 | ≤ 50 字符 | 标签名精确筛选 |

**规则**：`q` 和 `tag` **至少传一个**，都不传返回 422；两者都传时为 **AND** 关系（既含关键词又带该标签）。

**请求示例**

```bash
# 关键词搜索
curl "http://127.0.0.1:8000/api/notes/search?q=缓存"

# 仅按标签
curl "http://127.0.0.1:8000/api/notes/search?tag=redis"

# 关键词 + 标签（AND）
curl "http://127.0.0.1:8000/api/notes/search?q=穿透&tag=redis"
```

**响应示例（200）**

```json
{
  "code": 0,
  "message": "ok",
  "data": [
    {
      "id": 2,
      "title": "Redis 缓存实战",
      "content": "缓存穿透、击穿、雪崩的区别",
      "tags": ["redis"],
      "created_at": "2026-10-11T12:05:00",
      "updated_at": "2026-10-11T12:05:00"
    }
  ]
}
```

> 注意：搜索返回的 `data` 是**数组**（非分页结构），结果按 `updated_at` 倒序。

**缓存行为（重要）**

| 场景 | 缓存动作 |
|------|---------|
| 首次搜索（未命中） | 查 MySQL → 结果写入 Redis（key 为 `notes:search:{q}:{tag}`，TTL 300 秒） |
| 再次相同条件搜索 | 直接命中缓存返回，**不查数据库** |
| 搜索无结果 | 写入哨兵值 `EMPTY`，TTL 60 秒（防穿透） |
| 笔记被增/改/删 | 清空全部 `notes:search:*` 缓存，保证一致性 |
| Redis 不可用 | 记录 warning 日志，**自动降级直查 MySQL**，接口不报错 |

## 7. 核心机制说明

### 7.1 统一响应与异常处理

- 成功：路由直接返回 `ApiResponse`。
- 主动抛错：`raise HTTPException(404, "...")` → 由全局处理器包装成 `{code:404, message:..., data:null}`。
- 参数校验失败：Pydantic 抛出 `RequestValidationError` → 全局处理器包装成 422，错误明细放在 `data`。
- 好处：**业务类错误**（404 / 422 / 502）前端只需按一套结构解析，无需区分格式。

### 7.2 标签自动创建（F1）

创建/更新笔记时，对每个标签名：
1. 先按名称查询 `tags` 表；
2. 不存在则新建并 `flush` 拿到主键；
3. 已存在则直接复用。

配合标签名的**唯一索引**，不会产生重复标签。

### 7.3 缓存设计与防穿透（F6/F7）

```
key 设计：notes:search:{关键词}:{标签}
          例：notes:search:缓存:redis
          只传关键词：notes:search:缓存:    （标签段为空）
          只传标签：  notes:search::redis    （关键词段为空）

TTL：正常结果 300 秒（可配 SEARCH_CACHE_TTL）
     空结果  60 秒（可配 EMPTY_CACHE_TTL，短 TTL 防穿透）
```

**为什么需要防穿透**：若不缓存空结果，恶意或高频查询"不存在的关键词"时，每次都会穿透到 MySQL。写入 `EMPTY` 哨兵并在读到哨兵时直接返回空数组，即可挡住这类请求。

### 7.4 Redis 故障优雅降级（F9）

`cache.py` 中所有 Redis 操作都捕获 `redis.RedisError`：
- 读取失败 → 记 warning，返回"未命中"，业务继续查 MySQL；
- 写入失败 → 记 warning，跳过回填；
- 清理失败 → 记 warning，跳过。

**意义**：本机未安装 Redis 时，服务依然可正常启动并完整使用所有 CRUD/搜索功能，只是没有缓存加速。

### 7.5 参数校验规则汇总

| 位置 | 规则 |
|------|------|
| `title` | 去空白后长度 1–200，不能全空白 |
| `tags` | 自动 strip、去重、丢弃空串 |
| `page` | ≥ 1 |
| `page_size` | 1–100 |
| 搜索 `q` | ≤ 100 字符；与 `tag` 至少传一个 |
| 搜索 `tag` / 列表 `tag` | ≤ 50 字符 |

- **右侧**：**请求链路面板** —— 每次操作后，真实显示这次请求经过的每一层（浏览器 → `main.py` → `schemas.py` → `cache.py` → `crud.py` → MySQL/Redis → 统一响应），每层标注「执行 / 命中缓存 / 未命中 / 跳过 / 拦截 422」和该层的职责说明。

**两个最佳演示动作：**

1. **同一关键词连搜两次**：第一次链路显示 `Redis 缓存 → 未命中`，接着走 `crud.py` 查 MySQL；第二次若命中缓存，`crud.py` 与 MySQL 会显示「跳过」，能直观看到缓存省掉了哪一步。
   > ⚠️ 要看到第二次的「命中缓存 ⚡」，**必须先启动 Redis**；否则缓存层永远显示"未命中"并降级直查数据库（功能正常，只是没有加速效果）。
2. **两个搜索框都留空，直接点搜索**：链路会显示 `Pydantic 校验 → 拦截 422`，后面各层全部「跳过」，可以看清"参数校验"这一层是怎么把不合格请求挡在前面的。

该页面为单文件实现（`app/static/index.html`），CSS/JS 全部内联，**不依赖任何外部 CDN**。

## 11. 常见问题 FAQ

**Q1：启动时提示 `自动建表失败`，接口全部报 500？**
MySQL 未启动或数据库没建。先执行第 8.2 节第 1 步建库，并确认 `.env` 中密码正确，然后重启服务。

**Q2：没装 Redis，能用吗？**
能。项目对 Redis 做了故障降级：读/写/清理失败都只记 warning 日志，业务直查 MySQL。所有功能（除缓存加速外）均可正常使用。

**Q3：搜索接口报 422？**
`q` 和 `tag` 都没传。至少传一个，例如 `?q=缓存` 或 `?tag=redis`。

**Q4：下游 LLM 接口报 502？**
两种情况：① `.env` 里 `LLM_API_KEY` 未配置；② Key 无效/网络不通/超时。该接口独立，不影响 CRUD 与搜索。

**Q5：缓存何时失效？**
- 自然过期：正常结果 300 秒，空结果 60 秒；
- 主动失效：任何笔记的创建/更新/删除都会清空全部 `notes:search:*` 缓存。

**Q6：PUT 能否把内容清空？**
当前实现"只更新传入且非 null 的字段"，传 `"content": null` 与不传效果相同，因此暂时无法把已有内容改回空。可用传空字符串 `"content": ""` 达到近似效果。

**Q7：`.env` 会被提交到 git 吗？**
不会。`.gitignore` 已忽略 `.env`，只提交 `.env.example` 模板。请勿把真实密钥写入模板文件。

**Q8：打开 `/docs` 是白屏，但终端显示 200？**
文档页的排版资源（swagger-ui 的 JS/CSS）来自外部 CDN，**后端本身是正常的**。FastAPI 默认用 `cdn.jsdelivr.net`，该域名在国内网络经常超时，于是 HTML 骨架和浏览器标签标题能出来、页面却是空白。
本项目已在 [main.py](../app/main.py) 中把文档页资源改指向 `unpkg.com`（并关闭了默认的 `docs_url`/`redoc_url`，自定义 `/docs`、`/redoc`）。
若换到其他网络环境后仍白屏，按 F12 打开浏览器控制台看 `net::ERR_` 报错，把 `SWAGGER_JS_URL` / `SWAGGER_CSS_URL` 换成该环境可达的镜像源，或改为把静态文件下载到本地自托管。

## 12. 已知限制

| 限制 | 说明 | 可能的影响 |
|------|------|-----------|
| 搜索用 `LIKE %q%` | 前置通配符无法使用 B+ 树索引，数据量大时较慢 | 海量数据场景需换全文索引/搜索引擎 |
| 搜索接口不分页 | 直接返回全部匹配结果 | 结果集过大时响应体偏大 |
| 缓存整体失效 | 任一笔记变更清空全部搜索缓存 | 写多读少场景缓存利用率低（可用精准失效优化） |
| 内容是"只增不清" | 见 FAQ Q6 | 无法通过 PUT 置空内容 |
| 无鉴权 | 接口未做身份认证 | 仅适合内网/学习环境，公网部署需自行加认证 |
